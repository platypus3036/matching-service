### 🔗 주요 기능

#### 1️⃣ 주문 매칭 엔진
-   FIFO(First In First Out) 기반 주문 매칭 알고리즘 구현
-   실시간 매수/매도 주문 처리 및 우선순위 큐 관리
-   ReentrantLock 활용한 동시성 제어 및 성능 최적화

#### 2️⃣ 호가창 관리
-   실시간 호가 정보 관리 및 업데이트 메커니즘
-   KIS 데이터와 사용자 주문 통합 호가창 구성[8][11][14]
-   WebSocket 통한 실시간 호가 정보 브로드캐스팅[8]

#### 3️⃣ 체결 처리
-   매칭된 주문의 체결 로직 구현 및 처리[10]
-   체결 이벤트 발행 및 관련 서비스(주문, 사용자) 통보
-   체결 내역 저장 및 관리 시스템 구축

#### 4️⃣ 시장 데이터 처리
-   실제 시장 데이터 수집 및 처리 파이프라인
-   15초봉, 1분봉 등 다양한 시간대별 차트 데이터 생성
-   OHLC(시가, 고가, 저가, 종가) 데이터 관리 및 제공

#### 5️⃣ 성능 최적화
-   고성능 매칭 처리를 위한 자료구조 최적화
-   다중 스레드 환경에서의 안정적 동작 보장
-   대용량 주문 처리를 위한 메모리 및 CPU 사용 최적화

### 🌈 개선 사항

#### 1️⃣ 체결 대기 자료구조 변경 - <ins>ConcurrentSkipListMap 도입으로 동시성 및 성능 개선</ins>

**📌 문제점 (기존 `TreeMap<회사, TreeMap<주문>>` 구조)**
-   **동시 접근 시 자료구조 손상**: `TreeMap`은 동기화 처리가 되어있지 않아, 여러 스레드가 동시에 주문을 삽입/삭제할 경우 자료구조가 깨지거나 `ConcurrentModificationException` 발생 가능성.
    -   특히 `TreeMap`에 주문 삽입 시 발생하는 Red-Black Tree 정렬 과정에서 동시성 문제 발생 시 예측 불가능한 오류로 이어짐.
-   **성능 한계**: 높은 동시성 환경에서 `TreeMap`의 락 없는 접근은 데이터 부정합을 야기하며, 이를 외부에서 동기화 처리할 경우 성능 저하 발생.

**✅ 해결 (`ConcurrentSkipListMap`으로 변경)**
-   **동시성 안전성 확보**: `ConcurrentSkipListMap`은 여러 스레드에서 동시에 안전하게 사용 가능하도록 설계된 자료구조.
    -   내부적으로 Skip List 알고리즘과 CAS(Compare-And-Swap) 연산 등을 활용하여 락 경합을 최소화하면서 데이터 일관성 유지.
-   **정렬된 순서 유지 및 빠른 검색/삽입**: `NavigableMap` 인터페이스를 구현하여 키의 정렬 순서를 유지하며, 평균 O(log n) 시간 복잡도로 검색, 삽입, 삭제 작업 지원.
    -   일부 환경에서는 `TreeMap` 대비 특히 동시 삽입/삭제가 빈번할 때 더 나은 성능을 보일 수 있음[9].
-   **구조 변경**: `Map<회사코드, ConcurrentSkipListMap<주문가격, Queue<주문>>>` 형태로 변경하여 회사별, 가격별 주문 목록을 효율적으로 관리.

#### 2️⃣ 정교한 동시성 제어 - <ins>ReentrantLock 적용으로 데이터 정합성 강화</ins>

**📌 문제점 (자료구조 변경만으로는 부족한 정합성 보장)**
-   `ConcurrentSkipListMap`이 자료구조 자체의 동시성은 보장하지만, 복잡한 주문 매칭 로직(호가 업데이트, 주문 체결, 부분 체결 처리 등) 전체의 원자성을 보장하기에는 부족.
-   주문 매칭 서비스는 데이터 정합성이 최우선으로, 특정 종목에 대한 일련의 작업들이 외부 간섭 없이 안전하게 처리되어야 함.
-   기존 `synchronized` 키워드는 사용이 간편하나, 락 범위가 넓고 JVM 레벨에서 동작하여 멀티스레드 환경에서 불필요한 대기 발생 및 성능 저하 유발 가능성이 큼.

**✅ 해결 (`ReentrantLock` 도입)**
-   **세밀한 락 제어**: `ReentrantLock`은 특정 코드 블록(임계 영역)에 대해서만 락을 걸 수 있어, `synchronized`보다 정교한 동시성 제어 가능.
    -   예: 특정 회사(종목) 코드에 대한 주문 처리 로직 전체를 하나의 `ReentrantLock` 인스턴스로 보호하여, 해당 종목 관련 작업의 원자성 보장.
-   **성능상 이점**: 내부적으로 CAS 연산을 사용하여 락 상태를 관리하므로, 경합이 적은 상황에서는 `synchronized`보다 더 나은 성능을 제공할 수 있음.
-   **유연성**: 특정 종목별로 독립적인 `ReentrantLock` 인스턴스를 관리하여, 서로 다른 종목에 대한 주문 처리는 병렬적으로 수행 가능. 이를 통해 전체 시스템의 처리량 증대.
    -   하나의 메소드 전체가 아닌, 실제 공유 자원에 접근하고 수정하는 최소한의 범위에만 락을 적용하여 동시성 효율 극대화.
